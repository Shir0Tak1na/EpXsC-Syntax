# 2.3.x — D3 / D4 Plan

> Base: 2.3.0 (D1/D2 + diagnostics).
> Purpose: resume editor integration and Codex-like assistance without repeating the 2026-11-17 editor crash.

## 1. Hard constraints

- @codemirror/* and @lezer/* are external; never bundle a second CM6 runtime.
- main.js must not contain CM6/Lezer code; CI checks this.
- D3 is off by default, feature-flagged, fail-open, and has a circuit breaker.
- No experimental editor extension in the main vault before isolated-vault smoke.
- All model assistance is explicit-trigger; no automatic Markdown writes.

## 2. D3 — editor decorations

### D3.0 Root-cause spike (must finish first)

- Reproduce the old crash in an isolated vault with the incident build.
- Capture the console error verbatim.
- Confirm the bundled CM6 runtime hypothesis.
- Rebuild with CM6 external and verify the error disappears.
- Record Obsidian version, CM6 version, platform, and result in SMOKE.md.

### D3.1 Safe glue

- Thin adapter only: register extension behind a feature flag.
- CM6 glue module loaded lazily only when enabled.
- Catch errors in registration, editor construction, update, and decoration build.
- Circuit breaker: 3 errors per session -> disable D3 and log once.
- Crash-loop guard: persist an enabling marker before enabling; clear after first successful update; on next start, auto-disable if marker remains.

### D3.2 Decorations

- Decorate only EpXsC blocks, visible ranges only.
- Debounce docChanged; cap lines per block.
- Pure issue-to-decoration mapping in a Node-testable service.
- Error line: red dashed; warning line: orange wavy; approximate ranges labeled.
- Toggle on/off without restarting the vault via app.workspace.updateOptions().

### D3 gate

- Isolated-vault smoke passes; SMOKE.md recorded.
- Main vault opens all notes before and after enabling.
- Error injection triggers circuit breaker, not a crash.
- CI: no bundled CM6; pure mapping tests; jsdom/EditorView tests if feasible.
- First D3 release defaults off; evaluate default-on after one release cycle.

## 3. D4 — Codex-like assistance

### Principles

- Read-only first; no silent prose edits.
- Explicit command or keybinding; never on every keystroke by default.
- Model optional; local provider preferred; translation settings reused but independent.
- Every suggestion shows source, reason, and scope; user inserts manually.

### D4.1 Language services (no model)

- Word/phrase completion from the vault dictionary/grammar.
- Insertion candidates with part of speech, meaning, abbreviation, and lint preview.
- No network; fast; works offline.

### D4.2 Model-assisted actions

- Explain current EpXsC block (read-only).
- Suggest a corrected reference (F6-like) for an invalid block; validate unknown words/lint; never auto-insert.
- Complete a partial sentence from context; requires explicit trigger and confirmation.
- Optional local model; no request when disabled.

### D4.3 Safety

- Prompt/context minimality: current block + relevant dictionary entries only.
- No whole-vault exfiltration; no automatic notes.
- Output marked as suggestion; invalid reference disables insert.
- Separate assistance.enabled flag, default off.
