# 2.3.x — D3 / D4 Plan（rev. 2）

> Base: 2.3.0（D1/D2 + diagnostics）。
> 本版吸收 2026-11-17 事故复盘与外部审阅意见；不是“功能清单”，而是带证据门槛的施工计划。
> 硬规则：实验性编辑器扩展不得直接进主库；未记录 SMOKE = 未通过。

## 0. 事故证据状态

### 0.1 根因假设

初版 D3 打包了第二份 `@codemirror/*` 并调用 `registerEditorExtension`，导致主库所有笔记打不开。

当前假设：**打包的第二份 CM6 与宿主 CM6 实例冲突，扩展集在编辑器构造时抛错。**

这仍然只是假设，不能因为“改 external 后错误消失”就宣布已证实。外部化同时改变了依赖图、版本来源和加载路径，必须用证据区分。

### 0.2 根因证据矩阵

| 编号 | 证据 | 当前状态 | 通过条件 |
| :--- | :--- | :--- | :--- |
| R0 | 旧版本可复现崩溃 | 待做 | 隔离库中复现，保存控制台原文 |
| R1 | 旧 bundle 含 CM6/Lezer | 待做 | 依赖图或 bundle 扫描可证明 |
| R2 | 旧错误含 CM6 实例/扩展集特征 | 待做 | 错误文本可对应到假设 |
| R3 | external 后依赖来源正确 | 待做 | bundle 无 CM6；运行时只用宿主 API |
| R4 | external 后错误消失 | 待做 | 隔离库 smoke；不能单独证明 R0–R2 |

**结论规则：** R0–R3 未完成时，只能写“修复有效”，不能写“根因已确认”。

### 0.3 隔离复现协议

1. 新建空库，仅安装事故版本插件；复制 2–3 个含 EpXsC 块的笔记。
2. 启动 Obsidian，打开每个笔记，记录控制台首条错误和堆栈。
3. 保存事故 bundle 的依赖清单/构建 metafile。
4. 用 external 构建重复同一组操作；保存依赖清单/构建 metafile。
5. 将“根因确认”和“修复验证”分成两个 SMOKE 章节记录。

## 1. 范围与边界

### 目标

- D3：在编辑器中显示定位可靠的 EpXsC 诊断，但不阻塞编辑。
- D4：先做纯离线语言服务，再做显式触发的模型辅助。
- 所有失败必须 fail-open：笔记能打开，插件能加载，用户能关闭功能。

### 非目标

- 完整形式化语法解析器。
- 自动修改 Markdown。
- 把模型判断当作 lint 事实。
- 在 2.3.1 中同时交付 D3 装饰与 D4 模型功能。

## 3. D3.1 — 安全注册与生命周期（无装饰）

**发布节点：2.3.1 只验证“能安全注册、更新、卸载”，不显示任何下划线。**

### 3.1 错误边界

每个阶段都必须记录：阶段名、错误类型、首行堆栈、是否可重试；**不得记录笔记正文**。

| 阶段 | 捕获点 | 失败动作 |
| :--- | :--- | :--- |
| 注册 | `registerEditorExtension` | 放弃 D3，插件继续 |
| 构造 | ViewPlugin constructor | 返回空装饰，计一次错误 |
| 更新 | ViewPlugin update | 返回空装饰，计一次错误 |
| 构建 | decoration build | 返回空 RangeSet，计一次错误 |
| 卸载 | plugin unload / disable | 清理标记与定时器 |

**不计入熔断的错误：** 主动取消、AbortError、文档已销毁、版本不兼容（应直接禁用并单独提示）。

### 3.2 Circuit Breaker

- 同一会话最多 3 次**不同签名**的错误；签名 = 阶段 + 错误类型 + 首行堆栈。
- 同一签名重复出现只记录一次，不重复刷日志。
- 达到阈值：设置 `disabled-on-crash`，停止重建装饰，保留笔记编辑。
- 禁用后：不再调用 build/update；已有 decoration 清空。
- 重新启用必须由用户显式操作，不能在错误后自动恢复。

### 3.3 Crash-loop 状态机

状态：`disabled`、`enabling`、`active`、`disabled-on-crash`。

| 转移 | 条件 | 动作 |
| :--- | :--- | :--- |
| disabled → enabling | 用户开启 | 写 marker（version、timestamp、attempt） |
| enabling → active | 首次成功 update | 清 marker，记录一次成功 |
| enabling → disabled-on-crash | 构造/更新致命错误 | 保留 marker，熔断 |
| active → disabled-on-crash | 熔断 | 保留 marker，停止装饰 |
| disabled-on-crash → disabled | 用户关闭 | 清 marker |
| 任意 → disabled | 正常 unload/关闭 | 清 marker（仅正常路径） |

启动规则：若发现上次 marker 仍在，自动进入 `disabled-on-crash` 并提示用户；**不自动开启**。

边界：用户开启但从未打开编辑器，随后正常退出——正常 unload 必须清 marker，避免下次误判；若进程崩溃，marker 保留并触发保护。

### 3.4 卸载与恢复

- 关闭开关：清空 decoration、停止 update、清理 marker、`app.workspace.updateOptions()` 使配置生效。
- 禁用不能只改设置值；必须确认扩展不再运行。
- 恢复：仅在用户手动开启后重新注册；不在 session 内自动重试注册。

### 3.5 2.3.1 验收

- 隔离库：开启、打开、编辑、撤销、切换笔记、关闭、重启均不阻塞编辑。
- 不显示任何装饰；只证明生命周期安全。
- 关闭后无残留 decoration/定时器/日志刷屏。
- SMOKE 记录包含状态机、熔断阈值和错误签名。

## 4. D3.2 — 装饰（2.3.2）

### 4.1 坐标契约

- Core lint 输出：块内、LF 归一化、`line` 1-based、`column/start/end` 0-based。
- 文档绝对位置 = 块源码起始 offset + 前若干行长度 + 列偏移。
- 多行块必须按行累加；CRLF 已在 Core 归一化，适配层不得二次计数。
- 装饰只落在 EpXsC 块内；T/G 块的未知词由 D2 处理。
- 无法映射时 fail-open：跳过该诊断，不抛错。

### 4.2 可见范围与失效

- 只处理与 `view.visibleRanges` 相交的块。
- `docChanged` 后防抖重建；旧诊断不得跨文档复用。
- 每块行数超过上限：跳过整块并提示一次，或截断诊断；两者必须二选一并写入测试。
- 默认全量重建 RangeSet，规模上限内足够；增量优化不作为 2.3.2 前置条件。
- 错误行红色虚线；警告行橙色波浪线；近似范围保留“此行附近”。

### 4.3 验收

- 多行块、跨块、空块、超长块、可见范围边界均有测试。
- 文档修改后不残留旧装饰。
- 关闭开关后 decoration 清空。
- 纯函数装饰描述可在 Node 测试；CM6 只做薄适配。

## 5. D4 — Codex-like assistance

### 5.1 候选类型（防止 D4.1/D4.2 混在一起）

| 类型 | 数据来源 | 需要模型 | 发布范围 |
| :--- | :--- | :--- | :--- |
| 词条候选 | 词典/词根 | 否 | D4.1 |
| 语法候选 | 语法/例句 | 否 | D4.1 |
| 上下文建议 | 当前块 + 相关词条 | 是 | D4.2 |

### 5.2 D4.1 离线补全

- 从词库/词根/语法生成候选，显示词性、释义、缩写和 lint 预览。
- 用户显式触发；插入由用户确认。
- 词库变更后候选重建；不依赖网络/模型。
- 可与 D3 并行开发，但独立发布范围。

### 5.3 D4.2 模型辅助

- 只处理当前 EpXsC 块 + 用户显式选择的相关词条；不发送整个 vault。
- 发送前显示实际发送的文本与 endpoint（本地/远程）。
- 相邻句默认不发送；若启用，必须单独开关并显示范围。
- 相关词条上限、筛选规则、超时、失败提示写入设置。
- 输出是建议；未知词/lint error 禁止插入；永不自动写 Markdown。
- `assistance.enabled` 独立于 `translation.enabled`，默认关闭。

### 5.4 D4 测试

- 模型关闭时零请求；网络失败、超时、非法 JSON、空结果。
- 未知词/非法参考禁止插入。
- 发送预览与实际 payload 一致。
- 不记录笔记正文；不发送整个 vault。
