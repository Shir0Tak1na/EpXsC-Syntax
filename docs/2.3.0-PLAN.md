## 0. Incident record

D3 初版打包了 `@codemirror/view` 与 `@codemirror/state`，并在插件加载时调用 `registerEditorExtension`。

结果：主库中**所有笔记无法打开**。CI 全绿，因为 CI 只检查构建、测试和生成产物漂移，不启动 Obsidian。

恢复过程：

- 恢复 2.2.0 的安全产物；
- 临时将插件从 `community-plugins.json` 移除；
- 回退 D3 提交；
- 删除临时测试笔记；
- 重新启用安全的 2.2.0 构建。

### 根因判断（待隔离库确认）

最可能的原因：`main.js` 内打包了第二份 CM6，与 Obsidian 宿主的 CM6 并存，`instanceof` 判断失效，编辑器构造时抛错。每个 Markdown 编辑器创建时都会带上该扩展集，因此表现为所有笔记打不开。

预期特征：控制台出现 "Unrecognized extension value in extension set"，提示里提到多个 `@codemirror/state` 实例。

确认步骤（在隔离库中执行）：

- [ ] 用事故版本复现，记录控制台报错原文。
- [ ] 检查事故版本 `main.js`，确认含有打包进来的 `@codemirror` 代码。
- [ ] 将 CM6 改为 external 后重试，确认报错消失。

### 硬规则

1. 实验性编辑器扩展不得直接在主库测试；必须先通过隔离库冒烟，且该插件是库内唯一的社区插件。
2. `main.js` 不得包含 `@codemirror/*` 或 `@lezer/*`；由 CI 强制检查（见第 9 节）。

## 1. Goals and non-goals

### Goals

1. 在作者或 F5 把有问题的源码当作有效内容之前，让问题可见。2.3.0 通过阅读视图、Live Preview 非编辑状态的行级标记，以及不依赖 CM6 的诊断入口实现；编辑状态下的内联下划线属于 D3。
2. 阅读不受影响：移动端、Live Preview、源码模式、大笔记。
3. fail-open：诊断或编辑器集成失败时，笔记仍能打开，插件仍能加载。
4. 绝不自动修改 Markdown。
5. 除非用户明确启用翻译，否则绝不发起模型请求。

### Non-goals

- 对 EpXsC 所有构造的完整形式化解析。
- 把模型对语法的判断当作事实呈现。
- 自动修正作者的文本。
- 改写语言语义。
- 2.3.0 内的编辑器内联装饰（D3）与 token 级下划线。

## 3. D1 — range-aware lint

**现状：** 部分完成并有测试。

- 问题携带 `line`、`column`、`start`、`end`。
- 括号类（多余、不匹配、未闭合）为精确范围。
- 其余规则为整行近似范围，标记 `approximate: true`。
- fixture 已断言范围。

**偏移约定（需核对现有实现是否满足，不满足则修正后写入 ARCHITECTURE）：**

- `start` / `end` 相对于代码块文本，不是文档级偏移；文档级偏移由适配层加上块起点得到。
- Core 偏移基于 LF 归一化文本。CRLF 输入在 Core 入口归一化，适配层负责映射回编辑器位置。

**2.3.0 发布前：**

- [ ] 至少把一条 token 级规则（建议从 unit、filter-key、rank-range、consta、参数个数、spell 引用中选一条）从整行范围改为 token 范围。
- [ ] 增加断言 token 级精确范围的 fixture，不只覆盖括号。
- [ ] 增加 CRLF 输入的范围 fixture。
- [ ] `approximate` 保持对 UI 可见，不伪装成精确。

**2.3.x 或之后：** 其余规则逐步 token 化（D3 需要）。

## 4. D2 — reading / Live Preview diagnostics

**现状：** 已实现并做过手动冒烟。

- EpXsC 代码块：错误为红色虚线，警告为橙色虚线，悬停显示说明。
- T/G 块：未知词带 `epx-unknown` 点线标记与说明。
- 装饰在重新高亮后仍保留。

**已知限制（据我所知，需在隔离库确认）：** Live Preview 中，代码块处理器的渲染只在光标不在该块内时生效；光标进入后显示的是原始源码，D2 装饰不会出现。因此 D2 不覆盖正在编辑的块。该缺口由第 5 节的诊断入口补足，完整解决属于 D3。

**2.3.0 发布前：**

- [ ] 用自定义 DOM tooltip 替换原生 `title`，复用现有 tooltip 模块（不另写一套）。
- [ ] 移动端可用：点按所在行触发，不依赖悬停；lint 面板作为兜底入口。
- [ ] 增加 `aria-describedby` 等可访问性属性。
- [ ] 错误与警告在线型上也要有区别（例如虚线对波浪线），不只靠颜色。
- [ ] 近似范围的 tooltip 文案标明"此行附近"，不写成精确定位。
- [ ] 增加 fixture 或 DOM 级测试覆盖行包装层，防止重新高亮后装饰被静默移除。
- [ ] 确认渲染后的 HTML 行数与源码行数不一致时不添加包装层（当前的 fail-open 行为）。

## 5. 诊断入口（不依赖 CM6）

目的：在 D3 缺席时，仍让作者在编辑状态下看到问题。只使用 Obsidian 公开 API。

- 桌面端：状态栏显示当前笔记的错误数与警告数；随活动叶子切换和防抖后的文件修改更新。
- 移动端没有状态栏：通过命令面板的命令使用。
- 命令"打开当前笔记诊断"：打开已有 lint 面板。
- 面板条目点击后，用公开的 Editor API（如 `setCursor`、`scrollIntoView`）跳转到对应行。
- 受 `diagnostics.enabled` 控制；关闭后状态栏项消失，命令不执行。
- 只读；不写 Markdown；失败时记录一次日志并保持静默。

## 6. D3 — editor decorations（2.3.x spike，不阻塞 2.3.0）

### 6.1 实现规则

**CM6 来源**

- `@codemirror/*`、`@lezer/*` 全部 external，由宿主提供；通过 `registerEditorExtension` 注册。以锁定版本的官方示例插件 esbuild 配置为 external 列表基准。
- 不打包第二份 CM6，这是硬规则，不是"能提供就不打包"。

**fail-open 的真实边界**

- 抛错可能发生在编辑器构造和更新阶段，仅包住 `registerEditorExtension` 不够。
- 在 ViewPlugin 或 StateField 的 `update` / `buildDecorations` 内部捕获异常，出错时返回空装饰。
- 加熔断：同一会话内错误次数达到上限（暂定 3 次，常量可调）后停用 D3，并记录一次日志。
- D3 相关代码放在独立模块，仅在开关开启时于 try/catch 中懒加载；默认关闭时这段代码不会执行。

**运行时开关**

- 注册时传入一个数组；开关切换时修改数组内容，再调用 `app.workspace.updateOptions()`，无需重启库。

**崩溃循环保护（建议）**

- 启用 D3 前，在 `data.json` 写入"启用中"标记；首次成功完成一次编辑器更新后清除。
- 下次启动时若标记仍在，自动关闭 D3 并记录。插件本身仍能加载，所以该机制可行。

**性能**

- 只对 `visibleRanges` 内的块计算。
- `docChanged` 时防抖。
- 设置行数上限（沿用或参照 `MAX_HIGHLIGHT_LINES`）。

**分层**

- 适配层（`src/adapter/`）只做薄薄的 CM6 粘合。
- 把 lint 问题转为装饰描述的逻辑做成 Node 可测的纯函数（Service 层）。
- Core 不引入 CM6。

### 6.2 Spike 选项（按优先级）

1. **宿主提供的 CM6 + external**：已确定的路径（见 6.1）。
2. **无 CM6 回退**：第 5 节的诊断入口，已随 2.3.0 发布。
3. **推迟 D3**：若 spike 不安全，继续只发 D1/D2 与诊断入口。

### 6.3 D3 gate

D3 在 2.3.x 发布，当且仅当：

- 隔离库冒烟通过，且记录在 `SMOKE.md`；
- 插件加载不会阻塞笔记打开；
- 可在设置中关闭，且无需重启库；
- `main.js` 不含 CM6 运行时（CI 检查通过）；
- 熔断与错误注入测试通过；
- 首个发布版本默认关闭，经过至少一个发布周期后再评估默认开启。

## 7. D4 — Codex-like assistance

不属于 2.3.0。未来实现必须由用户显式触发，先只读，不写 Markdown，不把模型输出当作 lint 事实。

## 8. Settings

```
diagnostics: {
  enabled: true,
  editorDecorations: false
}
```

- `diagnostics.enabled` 为总开关：关闭后，D2 装饰、状态栏、命令全部停用，D3 不构造。
- `editorDecorations` 受总开关约束，默认 `false`。
- 迁移：旧配置缺少 `diagnostics` 时取默认值；缺字段逐项补默认。
- 校验：非法值保留上一次有效配置，不覆盖已保存配置。
- `enabled` 默认值取 `true`（D1/D2 只读且 fail-open），可在评审中调整。

CI 本身不是 D3 的发布门槛。metafile 检查能拦住"重复 CM6"类问题，jsdom 测试能拦住构造期与更新期抛错，但二者都不能替代隔离库冒烟。

### `SMOKE.md`

人工门槛固化成清单文件，每次发布前执行并留记录：

- 清单步骤固定（上表 Runtime 各项）。
- 每次记录：日期、构建哈希、Obsidian 版本、平台、通过/失败、备注。
- 未留记录视为未通过。

## 10. Rollback

每个实验性构建必须附带：

- 上一版 `main.js` / `manifest.json` / `styles.css` 的备份；
- 已测试的安全模式路径：在 `community-plugins.json` 中临时移除插件；
- 已记录的回退提交。

用户侧：笔记无法打开时，可在设置的第三方插件页关闭插件；若设置也不可用，手动编辑 `community-plugins.json`。该步骤写入 README 与 RELEASING。
