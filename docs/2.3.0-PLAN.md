# 2.3.0 Plan — 编辑器语法层

> Branch: `2.3.0-dev`  
> Base: 2.2.0 release candidate.  
> Goal: 让作者在写 EpXs 时先看到结构问题，而不是让 F5 替错误源句猜意思。

## 原则

- 不改变 EpXsC 语言语义；只把现有 lint 结果变成可定位的诊断。
- 所有诊断必须能降级：定位失败时退回整行/整块，不抛错、不阻塞渲染。
- 不自动改写 Markdown；补全/改写必须由用户确认。
- 默认关闭或轻量运行，不引入后台模型调用。

## D1 — lint range 化

**DoD**

- issue 包含：`line`（1-based）、`column`（0-based）、`start`、`end`。
- 至少覆盖：括号、块缩进、条款次序、limit、单位、筛选键、秩范围、术式引用、参数数量。
- 无法精确定位时使用整行范围，并带 `approximate: true`。
- fixtures 断言 range，不只断言 message。

**实现步骤**

1. `lintText` 内部 `push(level,line,message,start,end)`。
2. 括号栈记录开括号列；多出/不匹配括号记录当前列。
3. 词级检查用词在行内的索引；找不到时整行。
4. `lint-service` 原样透传，不改调用方。

## D2 — 阅读视图 / Live Preview 红色虚线下划线

**DoD**

- 对可定位的 issue，在渲染后的 token/行内加 `.epx-lint-underline`。
- 错误红色虚线，警告黄色；hover 显示 message。
- 定位失败或 renderer 不认识该位置时，不破坏块渲染。
- 移动端不依赖 hover；点击可打开 lint 面板。

## D3 — CodeMirror 装饰器

**DoD**

- 源码编辑器中只装饰当前文档的 EpXs 块。
- 不干扰 Live Preview 光标/选择/撤销。
- 诊断更新 debounce；切换文档取消旧 decoration。
- 无 Obsidian 环境时 Core 保持纯净。

## D4 — Codex 式辅助

**DoD**

- 补全、改写、语法解释均需显式触发。
- 不自动写入；不把模型输出当 lint 事实。
- 先做只读解释，再评估补全。

## 验收顺序

1. D1 fixtures + 全量测试。
2. D2 阅读视图单块 smoke。
3. D3 Live Preview smoke。
4. D4 单独安全审查，不阻塞 2.3.0 主体。
