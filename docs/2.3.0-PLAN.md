# 2.3.0 Plan — 安全优先的语法层

> Branch: `2.3.0-dev`
> Base: 2.2.0 release candidate.
> Status: D1/D2 implemented; D3 reverted after a runtime incident; plan rewritten 2026-11-17.
> Reviewers: please challenge the D3 assumptions and the release gate, not only the feature list.

## 0. Incident record

D3 initially bundled `@codemirror/view` and `@codemirror/state` and called `registerEditorExtension` at plugin load.

Result: **all notes became unopenable** in the main vault. CI was green because it only checks build, tests and generated-asset drift; it does not launch Obsidian.

Recovery:

- restored the 2.2.0 safe assets;
- temporarily removed the plugin from `community-plugins.json`;
- reverted the D3 commit;
- removed the temporary test note;
- re-enabled the safe 2.2.0 build.

Hard rule from this incident:

> No experimental editor extension may be tested directly in the main vault. It must first pass an isolated-vault smoke with the plugin as the only community plugin.

## 1. Goals and non-goals

### Goals

1. Make source problems visible before the author or F5 treats a bad source as meaningful.
2. Keep reading unaffected on mobile, Live Preview, source mode and large notes.
3. Fail open: if diagnostics or editor integration fail, the note still opens and the plugin still loads.
4. Never modify Markdown automatically.
5. Never make a model request unless the user explicitly enabled translation.

### Non-goals for this plan

- Full formal parser for every EpXsC construction.
- Model-based grammar judgment presented as fact.
- Auto-fixing the author's prose.
- Rewriting the language semantics.

## 2. Release train

| Version | Content | Gate |
| :--- | :--- | :--- |
| 2.2.0 | Optional translation layer (F5/F6/F8), default off | Existing release gates; publish next Asia/Shanghai day |
| 2.3.0 | D1/D2 safe grammar layer, tooltip polish | 2.2.0 released; isolated-vault smoke |
| 2.3.x | D3 editor decorations only if the spike is safe; otherwise deferred | D3 spike gate below |
| later | D4 Codex-like assistance | Separate security/interaction review |

The 2.2.0 candidate is already frozen on `main`. 2.3 work stays on `2.3.0-dev` until its gate passes.

## 3. D1 — range-aware lint

**Current state:** implemented and tested.

- Issues carry `line`, `column`, `start`, `end`.
- Exact ranges: brackets (extra/mismatch/unclosed).
- Approximate full-line ranges elsewhere, marked `approximate: true`.
- Fixtures assert ranges.

**Remaining before 2.3.0:**

- [ ] Convert unit, filter-key, rank-range, consta, argument-count and spell-reference issues from line-only to token ranges.
- [ ] Add a fixture asserting an exact token range, not only brackets.
- [ ] Keep `approximate` visible to the UI; do not pretend it is exact.

## 4. D2 — reading / Live Preview diagnostics

**Current state:** implemented and manually smoke-tested.

- EpXsC code blocks: red dashed line for error, orange dashed line for warning, hover title.
- T/G blocks: unknown words get an `epx-unknown` dotted mark and a title.
- Decoration survives rehighlight.

**Remaining before 2.3.0:**

- [ ] Replace native `title` tooltips with a larger, accessible tooltip (the current one is too small).
- [ ] Ensure the tooltip is usable on mobile (tap/selected line, not hover-only).
- [ ] Add a fixture or DOM-level test for the line wrapper, so a future rehighlight cannot silently remove decorations again.
- [ ] Confirm no wrapper is added when the rendered HTML line count does not match the source (current fail-open behavior).

## 5. D3 — editor decorations (spike only, not release-blocking)

### Why the first attempt failed

Unknown until reproduced, but the leading hypotheses are:

1. A second copy of CodeMirror 6 was bundled into `main.js`, conflicting with Obsidian's host instance.
2. The bundled CM6 version did not match the host's extension/state protocol.
3. `registerEditorExtension` was called at load time without a fail-open guard.
4. The extension threw during editor construction and took the whole editor down.

### Spike constraints

- Isolated vault, no other community plugins, sample notes only.
- No main-vault installation.
- Feature flag, default **off**.
- Registration wrapped in try/catch; on failure, log once and leave the plugin usable.
- Do not bundle a second CM6 if the host can provide it; document which API is used and why.
- No release until a full smoke passes: open, edit, undo, switch notes, toggle Live Preview/source, disable/enable plugin, restart Obsidian.

### Spike options, in order of preference

1. **Host-provided CM6 extension** with externalized `@codemirror/*`, if Obsidian exposes a stable supported path.
2. **No-CM6 fallback**: keep source-mode diagnostics as a gutter/status panel rather than editor decorations.
3. **Deferred D3**: ship 2.3.0 with D1/D2; revisit editor decorations later.

### D3 gate

D3 is included in 2.3.0 only if:

- isolated-vault smoke passes;
- plugin load never blocks note opening;
- feature can be disabled from settings without restarting the vault;
- `main.js` does not contain a duplicate CM6 runtime, or the duplication is proven harmless by the spike.

Otherwise 2.3.0 ships D1/D2 and D3 is explicitly deferred.

## 6. D4 — Codex-like assistance

Not part of 2.3.0. Any future implementation must be explicit-trigger, read-only first, and must not write Markdown or present model output as a lint fact.

## 7. Test matrix

| Layer | Test | Gate |
| :--- | :--- | :--- |
| Core | range fixtures, bracket/token ranges | unit |
| Core | unknown/word/pos/lint regressions | unit |
| Build | `npm test`, `npm run build`, `npm run check`, `npm run release:check` | CI |
| Asset | main.js drift check | CI |
| Runtime | isolated vault: open/edit/undo/switch notes | manual, blocking |
| Runtime | disable/enable plugin, restart Obsidian | manual, blocking |
| Runtime | large note (>50 lines block) | manual |
| Runtime | mobile/narrow window | manual |

CI alone is not a release gate for D3.

## 8. Rollback

Every experimental build must be accompanied by:

- previous `main.js` / `manifest.json` / `styles.css` backup;
- a tested safe-mode path (temporarily remove plugin from `community-plugins.json`);
- documented revert commit.

## 9. Open questions for reviewers

1. Is D3 worth the risk for 2.3.0, or should 2.3.0 be D1/D2 only and D3 move to 2.3.x?
2. Which Obsidian CM6 API is the supported, version-stable path for external plugins?
3. Should diagnostic tooltips be custom DOM (mobile-friendly) or use an existing Obsidian tooltip API?
4. Should the plugin ship with a `diagnostics.enabled` master switch separate from per-feature settings?
5. Is line-level evidence sufficient for V1, or must token-level underline ship before 2.3.0?

## 10. Acceptance for 2.3.0 (proposed)

- D1 exact ranges for at least brackets + one token-level rule.
- D2 red/orange line diagnostics in reading and Live Preview; unknown-word marks in T/G.
- Tooltip is readable and mobile-accessible.
- Isolated-vault smoke passes; main-vault install only after that.
- 2.2.0 is already released, or 2.3.0 release explicitly supersedes it.
- No automatic Markdown writes; translation remains opt-in/off.
